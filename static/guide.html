THE BIG PICTURE

方法、标准与执行，各有所长。

你提出任务并提供材料。Agent 结合你的要求，使用相关 Skills 和风险库完成工作；原文始终是事实判断的依据。

Skills指导「怎么做」

定义任务步骤、何时使用、参考哪些资料，以及交付什么格式的成果。

风险库规定「检查什么」

明确风险点、适用范围、公司基线和判定要点，形成完整审查的检查范围。

模型 / Agent负责「实际执行」

理解请求、读取材料、选择方法、结合标准分析，并调用工具生成与保存文件。

一次完整风险审查：确认任务与立场 → 加载审查 Skill → 读取主合同全文与所选风险库 → 逐项分析并给出依据 → 校验与保存报告。

普通事实问答可以直接读取原文回答，无需每次启动整份合同审查。明确选择某个 Skill，会要求 Agent 加载该 Skill；自然语言任务则可由 Agent 按用途说明选择。

01 / PERSONAL PREFERENCES

通用设置

前往设置 ↗

设置日常工作的默认偏好，保存在你的账号下。对话中明确指定的立场与回答要求优先。

设置项用途与实际影响
默认模型决定默认由哪个已接入模型处理任务，影响理解、推理、速度和用量。对话中明确选择的模型优先；默认模型需先在「模型与服务」接入。
默认我方立场例如甲方、乙方或实际公司身份。它影响 Agent 从谁的利益出发分析条款和提出建议；本次请求或对话中已确认的立场优先。
默认执行方式常规执行：允许当前工作目录的草稿写入和固定保存操作，额外命令按工具权限处理。谨慎执行：草稿写入和保存需确认。全权执行（云端沙箱）：允许沙箱内工具自动执行，包括额外命令，不逐项请求操作许可；仅适用于云端隔离沙箱。这些档位控制操作授权，不调整风险判定标准。
回答详略简洁、标准、详细，影响表达篇幅与解释深度。完整审查仍需覆盖启用风险点，不能因「简洁」跳过检查。
恢复系统默认清除个人通用偏好，使用系统默认值。不会删除合同、个人 Skills 或风险方案。
助手名称与用户称呼默认称呼助手为“合同助手”，称呼你为“您”。首次进入可填写或跳过，之后可在这里修改，后续对话会沿用。
业务背景与补充指引保存自己的业务领域和工作要求，仅用于本人的后续任务，不作为合同原文事实。

何时生效：新设置用于后续任务，不改变正在生成的答复。已明确选择执行方式的对话保留自己的选择；未单独选择的对话在下次执行时使用默认值。

02 / REUSABLE METHODS

Skills：沉淀任务方法

管理 Skills ↗

Skill 是 Agent 可以按需读取的任务指引。适合把反复使用的工作步骤、业务参考和输出要求保存下来，例如合同摘要、风险审查或条款修改。

内置只读，可复制公开示例只读，可复制我的个人维护与使用
设置项对 Agent 的作用
显示名称让你在列表中辨认任务，例如「付款安排专项检查」。主要服务于选择和管理。
用途说明告诉 Agent 什么时候适合使用这个 Skill。写清任务边界，例如「仅检查付款安排，整份合同审查使用合同风险审查 Skill」。
Markdown 正文提供实际步骤、分析要求和输出格式。Agent 加载后按指引执行，例如先读全文、再核对基线、最后输出依据和建议。
参考文件添加 Markdown / TXT 业务说明、范例或格式模板。在正文中写明何时读取哪份参考资料；添加文件不等于每次都会全文读取。
调用名称用于明确选择任务的标识，例如 /contract-review。可通过快捷入口、输入 / 搜索，或直接使用调用名称。
适用范围与启用范围决定谁能使用和维护；启用决定该 Skill 是否提供给 Agent。启用后按任务需要加载，不会让它在每次对话中自动执行。
复制与历史版本复制内置或公开 Skill 为个人版本后调整。历史版本可查阅；执行记录保留当次配置，便于理解结果使用了哪份指引。

它具体改变哪些行为？

  1. 选择任务方法用途说明帮助 Agent 判断相关性；明确选择 Skill 会要求它加载对应指引。
  2. 组织读取和分析正文与参考资料指导阅读顺序、分析重点和检查步骤。普通问答仍可直接进行。
  3. 形成所需成果输出格式指导报告结构、表格和文件要求，保存仍以真实文件与回执为准。

改方法用 Skill，改公司标准用风险库。

希望报告增加「谈判建议」一列，适合调整 Skill。希望公司付款基线从 60 日调整为 45 日，应修改所用风险方案。Skill 中的专项标准仅在该任务使用，不会自动合并进完整公司风险库。

生效时机：保存后查看 Skills 页的合同环境状态；空闲环境会同步，运行中的任务结束后应用。以环境显示的生效版本为准，历史执行仍保留原版本。

03 / REVIEW STANDARDS

风险库：明确审查标准

管理风险库 ↗

风险库以「审查方案」组织风险点。完整公司风险审查读取当前方案中全部启用项，结合合同内容与我方立场逐项分析。它既提供检查范围，也提供公司接受条件与判定口径。

设置项对风险识别的作用
方案名称与说明帮助辨认适用场景，例如采购合同、服务合同。只有被选中的方案进入本次审查；新建或复制后还需要选择使用。
我的默认 / 公开示例决定没有单独选择时使用哪份方案。顺序为：本次或对话选择 → 我的默认 → 公开示例。已有对话若已选择方案，修改个人默认不会覆盖该选择。
风险名称与编号名称说明要检查的问题，编号用于关联检查项与报告结果。它们帮助逐项记录覆盖情况，不是关键词匹配规则。
分类用于组织、筛选和归类风险，例如商法、财经、交付与服务。分类本身不决定是否命中。
适用行业与范围帮助 Agent 判断这项规则是否适用于当前合同与业务。启用项仍要逐项判断适用性；不适用需要说明原因。
严重程度提供风险重要性的分级口径，影响结果分级与关注顺序；调高等级不等于改变命中条件。
公司基线写清公司期望的条件或底线，例如「付款期限原则上不超过 60 日」。它是 Agent 比较合同约定的重要标准，应同时写清条件与例外。
判定要点将基线细化为可判断的问题，例如起算条件、例外约定、等效保护、跨条款约束。相比笼统描述，明确要点更能指导一致分析。
示例与检索提示示例帮助理解标准，检索提示帮助定位相关条款。它们只是辅助材料，不能用「未搜到关键词」代替全文阅读和缺失判断。
启用 / 停用方案须启用才可使用；方案内启用项进入完整审查范围，停用项不要求逐项覆盖。停用不会消除合同中的事实，也不代表合同没有这类风险。
复制、导入与版本可复制公开方案作个人调整、导入或导出 JSON，并载入历史版本后保存。公开示例由平台管理员维护；个人方案按账号独立使用，其他用户无法读取。
同一份条款，设置会怎样影响审查？交互示例 · 不保存任何配置

「验收并收到合规发票后，90 日内付款。」

假设我方为乙方，付款期限风险点适用，全文未发现改变期限的其他约定。

示例结论 · 命中

90 日超过 60 日基线

Agent 应指出付款期限偏离公司基线，引用原文并提出调整建议。实际分析还需要检查起算条件、例外和其他条款的影响。

这些天数仅为演示用的公司偏好，不是法律标准。本示例展示配置含义，不运行模型；实际结论取决于原文、完整规则和 Agent 分析。

检查过、命中与信息不足，要分开看。

「已检查 27 项」表示覆盖了 27 个风险点，不是发现 27 个风险。命中需要依据；未命中表示未发现偏离；信息不足表示材料不能支持完整判断；不适用单独呈现原因。

何时生效：保存方案后，后续执行读取所选方案的新版本，并保存当次配置快照。历史报告保持原结论；要用新标准评估旧合同，需要重新发起审查。

04 / MODEL CONNECTIONS

模型与服务

接入模型 ↗

个人用户可使用平台赠送额度，也可配置自己的供应商、API 密钥和模型。demo 用户仅使用平台试用模型，注册后可配置自己的模型。接入后，再在通用设置或对话中选择实际使用的模型。

设置项用途与实际影响
接入预设、服务地址预设帮助填写服务信息；服务地址决定请求发往哪里，需要与所用 API 产品和凭据一致。
供应商名称与标识名称方便辨认，标识用于区分接入配置。修改名称不改变模型能力。
API 密钥用于向模型服务认证。已配置时留空保留；选择清除密钥会停用该供应商。页面不返回已保存密钥的明文。
模型 ID 与显示名称ID 必须是服务实际支持的模型，显示名称用于列表展示。可以获取模型列表后添加，也可手动填写。
上下文上限声明模型可处理的上下文容量，参与运行时上下文管理。应按服务真实能力填写，调大数值不会让模型获得更长上下文。
输出上限限制单次生成预算。过低可能导致长报告截断，部分模型的思考也会占用输出预算；数值应符合服务规格。
启用、测试与应用供应商和模型均启用后才提供选择。「测试连接」验证接入可用性；「保存并应用」写入运行环境。运行中可能等待任务结束，以生效状态为准。

切换模型可能改变理解、推理、速度和用量，但不会自动改变风险库的公司基线。连接测试成功也不等于合同审查质量已经验证。

执行记录

查看执行记录 ↗

查看项用途与实际影响
范围与搜索筛选当前、已归档、最近删除或全部对话，定位需要回看的执行。只改变查看范围，不影响 Agent 行为。
工具与状态了解读取、写入、保存及错误信息，帮助定位任务停在哪里。过程状态应结合实际结果与保存回执理解。
配置快照记录当次使用的设置、模型、Skill 版本和风险方案，便于核对结果来源。执行记录按本人账号隔离。
环境与管理记录环境日志帮助排查云端运行环境启动等问题；管理员还可查看管理操作记录。读取记录不会主动唤醒环境。

使用方式规则与资料归属

A FEW THINGS TO KNOW

常见问题

第一次使用，需要先配好所有设置吗？

可以直接浏览公开示例，或领取 demo 上传自己的文档；注册后也可使用平台赠送额度。开始任务前确认我方立场和所用风险方案即可。优先使用内置 Skills；有稳定的重复任务后，再增加个人指引。

把所有 Skills 都启用，审查就会更全面吗？

启用只表示可供选择，Agent 会按任务需要加载。完整公司审查的覆盖范围主要由当前风险方案的启用项决定。用途清晰、边界明确的 Skills 更便于正确选择；多个 Skill 的要求也应避免相互冲突。

风险点没有启用，Agent 就完全不会提到它吗？

它不进入本次完整审查要求逐项覆盖的清单。但 Agent 仍可能在普通对话或其他任务中根据原文提到相关问题；停用不是禁止模型讨论，也不是确认风险不存在。

点击「接受风险」或「判断有误」，会自动修改风险库吗？

不会。风险处理意见保存为业务反馈与历史记录，不改写原审查结论，也不自动训练模型或修改风险库。需要改变标准时，应调整相应风险方案，再重新审查。

常规或全权执行，会跳过风险检查吗？

不会。「常规 / 谨慎 / 全权」控制文件写入、保存或额外命令等操作是否需要许可，不控制风险标准或审查深度。完整审查仍按相应 Skill 和启用风险项执行。

设置已保存，为什么结果没有立刻变化？

检查是否有对话单独选择的模型、执行方式或风险方案，再查看配置的环境生效状态。正在运行的任务不会被中途替换配置，历史结果不会自动重算；需要时在新配置生效后重新发起任务。

覆盖校验通过，是否意味着不会漏掉风险？

覆盖、引用与保存校验核对的是检查项是否齐全、依据能否定位以及文件是否保存。适用性、条款理解和风险判断仍由 Agent 完成，不能据此保证语义正确或识别所有风险。可以回到原文核对并继续追问。
